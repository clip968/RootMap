# 06. 트리 생성 결과 화면 구현

## 목표

AI가 생성한 학습 트리를 사용자가 명확하게 이해할 수 있는 계층 구조로 보여주고, 각 노드를 클릭해 상세 학습으로 진입할 수 있게 한다.

## 관련 명세

- 3. 핵심 사용자 시나리오: 시나리오 2
- 4. 화면 구성: 화면 2
- 10. UI 요구사항: 트리 UI
- 11. 검증 기준

## UI 필수 요소

- 루트 주제
- 선수지식 섹션
- 핵심 개념 섹션
- 부가 지식 섹션
- 오개념 섹션
- 이해 점검 섹션
- 각 노드 클릭 기능
- 재생성 버튼
- 저장 버튼

## 구현 작업

### 1. 노드 그룹핑

노드 타입별 섹션:

- `prerequisite` → 선수지식
- `core` → 핵심 개념
- `supplementary` → 부가 지식
- `misconception` → 오개념
- `quiz` → 이해 점검

### 2. 계층 구조 표시

Phase 1에서는 복잡한 그래프 대신 명확한 계층형 UI를 우선한다.

표시 방식 후보:

- 섹션별 리스트
- 들여쓰기 기반 트리
- 카드형 노드 리스트

필수 조건:

- 루트 주제가 가장 위에 있다.
- 노드 타입 구분이 명확하다.
- 노드는 클릭 가능하다.
- 노드 이해 상태가 시각적으로 표시된다.
- 추천 노드는 강조된다.

### 3. 노드 클릭 처리

- 노드 클릭 시 노드 상세 화면 또는 상세 패널을 연다.
- 필요한 값:
  - `tree_id`
  - `node_id`
  - 노드 기본 정보

### 4. 재생성 버튼

- 같은 주제로 `POST /api/trees/generate`를 다시 호출한다.
- 기존 트리를 대체할지 새 트리로 저장할지 정책을 정한다.
- Phase 1에서는 새 트리를 생성하고 해당 결과로 이동한다.

### 5. 저장 버튼

- 생성 API에서 이미 저장했다면 저장 완료 상태를 표시한다.
- 별도 저장 액션이 필요한 구조라면 저장 API를 분리한다.
- Phase 1에서는 생성 즉시 저장을 기본으로 하고, 버튼은 “저장됨” 피드백 용도로 둔다.

## 산출물

- 트리 결과 화면
- 타입별 노드 섹션 컴포넌트
- 노드 클릭 이벤트
- 상태/추천 강조 UI
- 재생성/저장 버튼

## 검증 기준

- 생성 결과가 다섯 섹션으로 구분되어 보인다.
- 사용자는 어떤 개념을 먼저 봐야 하는지 알 수 있다.
- 각 노드를 클릭할 수 있다.
- 추천 노드가 시각적으로 강조된다.
