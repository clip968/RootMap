# 08. 문서 업로드 및 분석 결과 UI

## 목표

사용자가 문서를 업로드하고 처리 상태를 확인한 뒤, 추출된 핵심 주제·개념·선수지식 요약을 보고 문서 기반 학습 트리로 이동할 수 있는 UI를 만든다.

## 관련 명세

- `rootmap_phase_3_spec.md` 14.1 문서 업로드 화면
- 동일 명세 14.2 문서 분석 결과 화면
- 동일 명세 16장 오류 처리 정책
- 동일 명세 18장 최소 품질 기준

## 구현 작업

### 1. 문서 업로드 진입점

기존 주제 입력 시작 화면과 구분되도록 문서 기반 학습 진입점을 제공한다.

필수 요소:

- 파일 업로드 영역
- 지원 형식 안내
- 파일 크기 제한 안내
- 처리 시작 버튼
- 처리 상태 표시 영역

지원 안내:

```text
지원 형식: PDF, TXT, MD
최대 파일 크기: 20MB
PDF는 텍스트가 포함된 파일을 권장합니다.
```

### 2. 업로드 UX

- drag & drop 또는 파일 선택 버튼
- 선택된 파일명·크기 표시
- 허용되지 않은 확장자 즉시 표시
- 업로드 중 로딩 상태
- 업로드 실패 메시지 표시

### 3. 처리 시작 UX

업로드 성공 후 `POST /api/documents/:documentId/process`를 호출한다.

상태 표시 예시:

```text
파일 업로드 완료
텍스트 추출 중
문서 구조 분석 중
개념 추출 중
학습 트리 생성 중
완료
```

구현 방식:

- MVP에서는 polling으로 `GET /api/documents/:documentId` 상태를 확인한다.
- 상태 값과 UI 메시지 mapping을 명확히 둔다.
- 실패 상태에서는 `processing_error`를 표시하고 재시도 가능성을 안내한다.

### 4. 문서 분석 결과 화면

문서 처리 완료 후 다음 정보를 보여준다.

- 문서 제목
- 문서 요약
- 핵심 주제
- 추출된 핵심 개념 목록
- 추론된 선수지식 목록
- 생성된 학습 트리로 이동 버튼

예시 구성:

```text
문서 제목: Attention Is All You Need
핵심 주제: Transformer

문서 핵심 개념:
- Scaled Dot-Product Attention
- Multi-Head Attention
- Positional Encoding

필요한 선수지식:
- Vector
- Matrix Multiplication
- Dot Product
- Softmax
```

### 5. source type 표시

분석 결과에서도 다음 구분이 보이면 좋다.

- 문서에 직접 등장한 개념
- 문서 이해를 위해 추론된 선수지식

표시 예:

```text
문서 핵심 개념: explicit
선수지식: inferred 또는 explicit prerequisite
```

### 6. 오류 상태 UI

대표 오류:

- 텍스트 추출 실패
- 문서가 너무 김
- 개념 추출 품질 낮음
- LLM 처리 실패
- 네트워크 오류

오류 메시지는 명세 16장의 문구와 최대한 맞춘다.

## 완료 조건

- 사용자가 PDF/TXT/MD 파일을 선택하고 업로드할 수 있다.
- 업로드와 처리 상태를 단계별로 확인할 수 있다.
- 처리 완료 후 문서 제목, 요약, 핵심 개념, 선수지식이 표시된다.
- 문서 기반 학습 트리로 이동할 수 있다.
- 처리 실패 시 이유와 다음 행동이 안내된다.
