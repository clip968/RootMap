# 07. 노드 상세 설명 플로우 구현

## 목표

사용자가 특정 노드를 클릭했을 때 쉬운 설명, 예시, 비유, 오개념, 이해 점검 질문, 다음 추천 노드를 확인할 수 있게 한다.

## 관련 명세

- 3. 핵심 사용자 시나리오: 시나리오 4
- 4. 화면 구성: 화면 3
- 5. AI 출력 스키마: 노드 상세 설명 응답 스키마
- 6. 프롬프트 설계: 노드 상세 설명 프롬프트
- 9. API 명세

## API

```http
POST /api/nodes/:nodeId/detail
```

Request:

```json
{
  "tree_id": "uuid"
}
```

Response:

```json
{
  "node_id": "uuid",
  "title": "Borrowing",
  "easy_explanation": "...",
  "example": "...",
  "check_questions": []
}
```

## UI 필수 요소

- 노드 제목
- 노드 유형
- 쉬운 설명
- 왜 필요한지
- 예시
- 비유
- 관련 개념
- 자주 하는 오해
- 이해 점검 질문
- 다음 추천 노드

## 구현 작업

### 1. 상세 API 구현

처리 순서:

1. `nodeId`로 노드 조회
2. `tree_id`로 전체 트리 컨텍스트 조회
3. 이미 `detail_json`이 있으면 캐시 응답
4. 없으면 LLM 상세 프롬프트 호출
5. JSON 스키마 검증
6. `learning_nodes.detail_json`에 저장
7. 클라이언트에 반환

### 2. 선수지식 컨텍스트 구성

LLM에 전달할 컨텍스트:

- 현재 주제
- 선택 노드 제목
- 노드 타입
- 현재 노드의 prerequisites
- 관련 children
- 전체 recommended_order 일부

### 3. 상세 화면/패널 구현

표시 섹션:

- 왜 필요한지
- 쉬운 설명
- 예시 코드 또는 구체 예시
- 비유
- 자주 하는 오해
- 이해 점검 질문
- 다음에 볼 노드

### 4. 로딩/에러/캐시 처리

- 처음 클릭 시 로딩 표시
- 상세 생성 실패 시 재시도 버튼 제공
- 이미 생성된 상세는 재호출 없이 표시

## 산출물

- `POST /api/nodes/:nodeId/detail`
- 노드 상세 LLM service
- 상세 JSON 저장 로직
- 노드 상세 UI
- 로딩/에러/재시도 UI

## 검증 기준

- 노드를 클릭하면 상세 설명이 생성된다.
- 상세 설명에는 쉬운 설명, 예시, 질문이 포함된다.
- 동일 노드를 다시 열면 저장된 상세 설명을 재사용한다.
- 초보자가 이해 가능한 문장으로 표시된다.
